# Что доработано

Проект доработан как Android-прототип без серверной части и внешних API ресторанов.

## Реализовано

- Расширенная SQLite-схема: пользователи, предпочтения, рестораны, меню, отзывы, рецепты, история, избранное, справочники, логи.
- Демо-данные ресторанов, меню, отзывов и ингредиентов.
- Регистрация/вход через e-mail, восстановление пароля через временный пароль `123456`, выход из аккаунта.
- Расширенный профиль предпочтений: кухни, диета, аллергии, бюджет, время приготовления, уровень навыков, сброс предпочтений.
- Единый запрос «Что поесть сегодня?»:
  - 1–3 ресторана рядом;
  - 1–2 домашних рецепта;
  - вариант доставки;
  - обоснование выбора;
  - сохранение запроса и выбранных вариантов в историю.
- Поиск ресторанов с фильтрацией по кухне, бюджету, диете и аллергенам.
- Просмотр карточки ресторана, меню и отзывов.
- Добавление ресторанов в избранное.
- Генерация локальных персонализированных рецептов с временем, ингредиентами и списком покупок.
- Режим «Что приготовить из холодильника?» с выбором продуктов, поиском, категориями, 3–7 рецептами и докупкой не более 3 позиций.
- Сравнение «Ресторан или Дом» по цене, времени и калорийности.
- История выбранных ресторанов/рецептов, повтор варианта и очистка истории.
- Админ-экраны:
  - пользователи: поиск, просмотр профиля, блокировка/разблокировка, удаление;
  - рестораны: добавление, редактирование, удаление, добавление блюд, просмотр меню;
  - справочники: кухни, диеты, аллергены, категории продуктов;
  - отчёты: базовая статистика, популярные запросы, рестораны и рецепты.

## Важное ограничение

Функции геолокации, реального бронирования, доставки, внешних ресторанных API, серверной PostgreSQL и промышленной LLM-валидации не могут быть полноценно реализованы внутри локального архива без серверной инфраструктуры и ключей API. Они заменены рабочими локальными аналогами на SQLite-данных.

## Безопасность

Захардкоженный ключ Gemini удалён из `BuildConfig.java`. Приложение работает на локальной генерации. Для реальной LLM-интеграции ключ нужно передавать через безопасную конфигурацию сборки/сервер, а не хранить в исходниках.
